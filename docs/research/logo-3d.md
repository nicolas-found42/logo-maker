# Scriptable 3D logo pipelines (headless, macOS arm64) — research

Scope: practical 3D→logo techniques that can be scripted and rendered headless on this machine (macOS arm64, 48 GB RAM, Python+uv, Node+Bun, Homebrew). Brand: “Chief of Staff” — private AI workspace that remembers meetings; owner reviews next steps; tagline “Remembers the meeting. You make the call.” Brand colors: #1E4A7A blue, #2F6B4F green, #B45309 amber, #F2C14E gold, #F8F6F1 paper, #16232E ink; fonts Playfair Display (variable, wght 400–900) + Open Sans, OFL, at `/tmp/brandfonts/`. Primary sources only (official docs, GitHub, PyPI/npm, release notes); probe evidence from `/tmp/logo3d/` below. No AI image/3D generation APIs were called; no system-wide installs were made.

## Verdict up front

**Best scriptable chain (proven on this Mac): `fontTools` instance the variable font → `bpy` (Blender 5.2.3, PyPI, Python 3.13, macOS arm64) text object → extrude/bevel → Principled BSDF brand-blue material → EEVEE render (paper world, sun+area lights) → transparent or paper PNG.** It produced valid 800×800 PNGs in seconds with zero GUI, and Blender reads back the three.js `.gltf` for a shared shading stage. **Best CAD/vector chain: `build123d` (`Text`→`extrude`→STEP/STL/glTF + `project_to_viewport`→SVG line-art) + `trimesh` + matplotlib raster (no OpenGL needed).** three.js is excellent for geometry/web, but true headless raster still needs a browser (Playwright/Puppeteer) or the Blender round-trip — there is no pure-Node WebGL renderer in the stack. Treat all 3D as an *accent* system over a flat-first master logo (see §5); the 3D renders are for hero/OG-style moments, never the favicon.

## 1. Blender

**Two headless entry points.** (a) The `bpy` PyPI wheel (“Blender as a Python module”) — current release 5.2.3 ships `bpy-5.2.3-cp313-cp313-macosx_11_0_arm64.whl` (245 MB), `requires_python: ==3.13.*`, summary “Blender as a Python module” [https://pypi.org/project/bpy/4.3.0](https://pypi.org/project/bpy/4.3.0) and the wheel index [https://download.blender.org/pypi/bpy](https://download.blender.org/pypi/bpy). This is the chain this research probed. Note the upstream caveat that the Python-module build is a build option, not an officially distributed release artifact [https://developer.blender.org/docs/handbook/building_blender/python_module](https://developer.blender.org/docs/handbook/building_blender/python_module) — in practice the PyPI wheel installs and runs (observed, §6). License: GPL-3.0 (PyPI `license` field); renders are the user's work and are not copylefted by the tool. (b) The standalone app’s background mode: `-b/--background` (“Run in background… used for UI-less rendering”) [https://docs.blender.org/manual/en/latest/advanced/command_line/arguments.html](https://docs.blender.org/manual/en/latest/advanced/command_line/arguments.html), e.g. `blender -b -P script.py`. This needs the Blender application bundle (a system-level install — outside the no-system-install constraint; it would need the user's permission), whereas the `bpy` wheel needs only `uv pip install bpy==5.2.3` inside a Python 3.13 venv.

**SVG → extruded curves.** Blender’s SVG importer “Imports a SVG file as one or more curve objects” [https://docs.blender.org/manual/en/latest/files/import_export/svg_curve.html](https://docs.blender.org/manual/en/latest/files/import_export/svg_curve.html), so the existing 2D vector chain (fontTools + skia-pathops) can feed Blender: import curves → convert/keep as curves → `extrude` + `bevel_depth`/`bevel_resolution` → mesh. Text objects are the shortcut for the ‘C’: `cu.body = "C"; cu.extrude = 0.15; cu.bevel_depth = 0.02`.

**Variable-font weight: instance first.** Text-object properties cover font selection and triangulation (Delaunay/Sweep) [https://docs.blender.org/manual/en/latest/modeling/texts/properties.html](https://docs.blender.org/manual/en/latest/modeling/texts/properties.html) but expose **no wght-axis instancing API** in `bpy`. The probe confirmed the behavior: `bpy.data.fonts.load()` on the variable `PlayfairDisplay[wght].ttf` loads “Playfair Display Regular” (default instance). Therefore: `fontTools.varLib.instancer.instantiateVariableFont(font, {"wght": 900})` → save `PlayfairDisplay-Black.ttf` → load that in Blender. The instanced file has no `fvar` left and `OS/2.usWeightClass == 900` (observed, §6). Same rule applies to every chain (build123d `Text`, three.js, OpenSCAD): always instance the weight you want before extrusion.

**Materials.** Principled BSDF covers the brand’s “paper / clay / enamel / metal” family with the same node: Base Color + Roughness (+ Metallic / Clearcoat for enamel). The probe used paper world (#F8F6F1), brand-blue Principled (#1E4A7A), sun + area lights. Body text to preserve: EEVEE + Cycles in Blender 5.2 both select engines via `scene.render.engine`.

**Cycles vs EEVEE on Apple Silicon.** The manual documents Cycles GPU backends including **Metal** (“Select either CUDA, OptiX, HIP, oneAPI, or Metal” for GPU rendering) [https://docs.blender.org/manual/en/latest/render/cycles/gpu_rendering.html](https://docs.blender.org/manual/en/latest/render/cycles/gpu_rendering.html). On this Mac the probe observed: EEVEE renders headless via `bpy` in ~1 s; Cycles **CPU** renders headless too (used for the transparent pass, 32 samples). Practical guidance: use **EEVEE for iteration** (fast, forgiving, ideal for logo passes) and **Cycles (CPU or Metal) for the final hero** when global-illumination softness matters; both run without a window server in the `bpy` environment. Do not block the pipeline on Metal availability — CPU fallback is proven.

**Line-art back to vector: Freestyle + SVG exporter — not in the pip wheel.** The manual documents the Freestyle SVG Exporter add-on: “This add-on can export your Freestyle Renders into an SVG file. It can fill contours with their material color” [https://docs.blender.org/manual/en/latest/render/freestyle/export_svg.html](https://docs.blender.org/manual/en/latest/render/freestyle/export_svg.html). The probe observed that **`bpy.ops.preferences.addon_enable(module='render_freestyle_svg')` fails in the PyPI wheel** (`ModuleNotFoundError: No module named 'render_freestyle_svg'`), and `bpy.ops.export.render_freestyle_svg` does not exist there — the trimmed wheel does not bundle that add-on, and the add-on file is no longer at the old raw-GitHub path (404). Freestyle PNG rendering itself works (probe rendered `bpy_C_freestyle.png`). For production SVG line-art from 3D, prefer (i) the standalone Blender app (needs user permission for the system install) with the bundled add-on, or (ii) the build123d `project_to_viewport` → `ExportSVG` path (§3), which is already proven headless here.

**Transparent PNG.** `scene.render.film_transparent = True` + `image_settings.color_mode = 'RGBA'` + PNG produces an alpha logo file; the manual’s Film settings document the `Transparent` option (“Render the background transparent, for compositing”) [https://docs.blender.org/manual/en/latest/render/cycles/render_settings/film.html](https://docs.blender.org/manual/en/latest/render/cycles/render_settings/film.html). Observed: `bpy_C_transparent.png` is 800×800 RGBA with transparent corners.

## 2. three.js

**Geometry from SVG or text.** three.js ships `SVGLoader` (SVG → `Shape`/`Path` arrays) and the standard recipe is `SVGLoader → Shape → ExtrudeGeometry` for extruded logos; `TextGeometry` generates text as one geometry from a loaded `Font` obtained via `FontLoader` (the `TextGeometry` source itself points to the `FontLoader` page) [https://github.com/mrdoob/three.js/blob/r185/examples/jsm/geometries/TextGeometry.js](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/geometries/TextGeometry.js), with the public docs at [https://threejs.org/docs/pages/SVGRenderer.html](https://threejs.org/docs/pages/SVGRenderer.html) (import path `three/addons/...`). TTF → `typeface.json` conversion is done by **facetype.js** (“A simple way to convert ttf files to typeface.json font files” [https://discourse.threejs.org/t/facetype-js-a-typeface-js-generator/53](https://discourse.threejs.org/t/facetype-js-a-typeface-js-generator/53); repo [https://github.com/gero3/facetype.js](https://github.com/gero3/facetype.js), MIT, 730★). Two empirical notes from the probe: facetype.js is a **web tool, not an npm package** (`bun add facetype.js` → registry 404), so headless TTF→geometry is better done with **opentype.js** (npm `opentype.js@2.0.0`, `font.getPath('C', 0, 0, 100)` → `THREE.Shape` → `ExtrudeGeometry`), which the probe used to extrude the Playfair ‘C’ (20,130 verts) and export `.gltf` under Bun/happy-dom (GLTFExporter needs DOM `FileReader`; happy-dom polyfill required — observed). three.js itself is MIT, 117,983★ [https://github.com/mrdoob/three.js](https://github.com/mrdoob/three.js); probed version 0.187.0.

**Headless raster.** three.js renders to WebGL — there is no built-in Node renderer. Headless options: (a) **Playwright/Puppeteer + Chromium** screenshot of a small HTML scene (needs a browser download ~150 MB, local, no system install — not run live here); (b) **headless-gl** (`gl` npm) — historically fragile on arm64/macOS, not attempted; (c) **round-trip through Blender**: export `.gltf` (proven) → `bpy.ops.import_scene.gltf` (proven) → EEVEE PNG (proven, §6). Vector output: `SVGRenderer` is an addon that renders a scene as SVG elements [https://threejs.org/docs/pages/SVGRenderer.html](https://threejs.org/docs/pages/SVGRenderer.html), but community reports note limitations with materials/transparency (triangulated faces showing through transparent surfaces) [https://discourse.threejs.org/t/svgrenderer-showing-internal-triangle-earcut-geometry-on-transparent-surfaces/16455](https://discourse.threejs.org/t/svgrenderer-showing-internal-triangle-earcut-geometry-on-transparent-surfaces/16455) — fine for flat-ish linework, not a substitute for real SVG authoring. Recommendation: use three.js if a web/interactive logo is wanted; for static brand PNGs, prefer the `bpy` chain or the build123d chain, and reuse Blender as the renderer when a three.js scene already exists.

## 3. CAD-style chains

**build123d (recommended CAD chain; proven).** “A Python-based, parametric (BREP) modeling framework… Built on the Open Cascade geometric kernel” [https://build123d.readthedocs.io/en/stable](https://build123d.readthedocs.io/en/stable); examples “organized from simple to complex… the best way to absorb the concepts” [https://build123d.readthedocs.io/en/stable/introductory_examples.html](https://build123d.readthedocs.io/en/stable/introductory_examples.html); install `pip install build123d` [https://build123d.readthedocs.io/en/latest/_sources/installation.rst.txt](https://build123d.readthedocs.io/en/latest/_sources/installation.rst.txt). Apache-2.0, 3,677★ [https://github.com/gumyr/build123d](https://github.com/gumyr/build123d); PyPI 0.13.0, `requires_python >=3.11, <3.15` (pure-Python wheel; OCCT ships inside). Relevant APIs (docs + probe): `Text("C", font_path=..., font_size=...)` in a `BuildSketch`, `extrude(amount=...)`, `export_step`/`export_stl`/`export_gltf`, `project_to_viewport(viewport_origin, viewport_up)` → visible/hidden `Edge` lists, `ExportSVG(...).add_shape(...).write(...)` for orthographic/isometric SVG projections. The probe produced `cad_C.step/.stl/.gltf`, `cad_C_projection.svg` (32 visible edges), and a matplotlib PNG (see §6). Note the older `MesherUnit`/`bevel_amount` kwargs do not exist in 0.13 — use `export_gltf`/`export_obj` and post-extrude `chamfer`/`fillet` for bevels.

**CadQuery (alternative, not probed live).** “An intuitive… Python library for building parametric 3D CAD models” [https://cadquery.readthedocs.io/en/latest](https://cadquery.readthedocs.io/en/latest) with `Workplane.text()`-style creation and SVG export (`toSvg`/`exportSVG`) [https://cadquery.readthedocs.io/en/latest/_modules/cadquery/cq.html](https://cadquery.readthedocs.io/en/latest/_modules/cadquery/cq.html); import/export formats include DXF, SVG, STEP, STL, glTF [https://cadquery.readthedocs.io/en/latest/importexport.html](https://cadquery.readthedocs.io/en/latest/importexport.html). Apache-2.0, 6,083★ [https://github.com/CadQuery/cadquery](https://github.com/CadQuery/cadquery); PyPI 2.8.0. Prefer build123d for new work (finer exports, active docs); CadQuery remains viable for OCCT portability.

**OpenSCAD (scriptable text+SVG, app install required).** `text()` “creates text as a 2D geometric object, using fonts installed on the local system or provided as separate font file” [https://files.openscad.org/documentation/manual/Text.html](https://files.openscad.org/documentation/manual/Text.html); `import("file.svg")` imports “the geometric structure of SVG files” [https://files.openscad.org/documentation/manual/SVG_Import.html](https://files.openscad.org/documentation/manual/SVG_Import.html), typically combined with `linear_extrude()`. Headless use is first-class: “Using OpenSCAD in a command line environment… `openscad [options] file.scad`” with `-o` output and PNG render modes [https://files.openscad.org/documentation/manual/Using_OpenSCAD_in_a_command_line_environment.html](https://files.openscad.org/documentation/manual/Using_OpenSCAD_in_a_command_line_environment.html). GPL-2.0 (COPYING), 10,630★ [https://github.com/openscad/openscad](https://github.com/openscad/openscad). Not probed live (needs the OpenSCAD app bundle = system install = user permission). Good fit for quick extruded-text logos; rendering is OpenGL-based (preview/render), so stills are fast but materials are minimal.

**manifold3d (mesh-boolean / cross-section kernel).** Python bindings expose `CrossSection` (polygons, even-odd, boolean) and `Manifold.extrude` (“Library for geometric robustness”) [https://github.com/elalish/manifold/blob/master/bindings/python/examples/all_apis.py](https://github.com/elalish/manifold/blob/master/bindings/python/examples/all_apis.py); Apache-2.0, 2,400★ [https://github.com/elalish/manifold](https://github.com/elalish/manifold); PyPI 3.5.4 ships `macosx_11_0_arm64` wheels for cp310–cp313 (1 MB). Role: fast, robust meshing/booleans *around* the mark (e.g. a pill/badge enclosing the ‘C’), not a text-shaping tool by itself — pair it with trimesh for loading/export, or with build123d for the letter. No renderers; export and hand off to `bpy`/`trimesh` for stills.

## 4. Other approaches

**Isometric / 2.5D vector.** [jdan/isomer](https://github.com/jdan/isomer) (MIT, 2,906★, npm `isomer@0.2.6`): “Simple isometric graphics library for HTML5 canvas” — cuboids/prisms in SVG/canvas, good for an isometric ‘C’ mark with pure-vector output. [metafizzy/Zdog](https://github.com/metafizzy/zdog) (10,696★, npm `zdog@1.1.3`, MIT via npm; no LICENSE file in the GitHub repo): “Flat, round, designer-friendly pseudo-3D engine for canvas & SVG”. Both are 2.5D, fast, and vector-friendly, but neither does real extruded type with bevels — use for isometric accents, not for the Playfair serif letterform.

**Quick renders: trimesh / pyrender / vedo.** [trimesh](https://github.com/mikedh/trimesh) (MIT, 3,719★, PyPI 5.2.0) loads/manipulates meshes and ships an offscreen-render example [https://github.com/mikedh/trimesh/blob/main/examples/offscreen_render.py](https://github.com/mikedh/trimesh/blob/main/examples/offscreen_render.py), but offscreen rendering on macOS still needs a GL context. [pyrender](https://github.com/mmatl/pyrender) (MIT, 1,474★, PyPI 0.1.45) is glTF-compliant PBR — Offscreen mode needs EGL or OSMesa on headless servers [https://pyrender.readthedocs.io/en/latest/examples/offscreen.html](https://pyrender.readthedocs.io/en/latest/examples/offscreen.html), and on macOS it needs the mmatl `pyglet` fork for OpenGL contexts [https://pyrender.readthedocs.io/en/latest/install](https://pyrender.readthedocs.io/en/latest/install). [vedo](https://github.com/marcomusy/vedo) (MIT, 2,275★, PyPI 2026.6.3) can render non-interactively: “`vedo bunny.obj --output bunny.png`” and `Plotter(offscreen=True)` [https://vedo.embl.es/docs](https://vedo.embl.es/docs) — but VTK offscreen without X11/EGL/OSMesa can segfault in headless environments (community TIL [https://agents.stackoverflow.com/tils/e35438ee-26a3-4251-a6c3-4a41d92ae317?page=1&tag=vedo](https://agents.stackoverflow.com/tils/e35438ee-26a3-4251-a6c3-4a41d92ae317?page=1&tag=vedo)). None was installed live here; the probe's pragmatic stand-in — **trimesh + matplotlib Agg `Poly3DCollection`** — produced the CAD PNG without any GL stack (§6). For logo stills, that is sufficient; reserve pyrender/vedo for textured PBR previews.


**AI 3D generators — needs-permission, not recommended for the type-driven mark.** [microsoft/TRELLIS](https://github.com/microsoft/TRELLIS) (MIT code, 14,227★) generates meshes/Gaussians from text/image, but “tested only on Linux… NVIDIA GPU with at least 16 GB of memory… CUDA” per its README (observed via GitHub API) — not runnable on this Mac locally without a discrete GPU/remote host. [Tencent-Hunyuan/Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2) (15,374★) is under the **Tencent Hunyuan 3D 2.0 Community License**: Territory excludes the EU/UK/South Korea; commercial use free below 1 M MAU, license request above; “Tencent claims no rights in Outputs” (§6.d of the LICENSE, observed via GitHub API). [VAST-AI-Research/TripoSR](https://github.com/VAST-AI-Research/TripoSR) (MIT code+weights per README, 7,349★) is “fast feedforward reconstruction from a single image” (~6 GB VRAM, NVIDIA A100 benchmark) — PyTorch/CUDA-oriented; macOS MPS support is undocumented. All three are image-to-3D hallucinators: wrong tool for a precise Playfair letterform, and all need user permission (AI generation + likely remote GPU) before any use. Do not reach for them to “design” the logo.

## 5. Design guidance: when 3D logos work vs. fail

Use first-party brand/design sources, because the flat-first rule is not taste — it is a legibility requirement:

- **Apple (HIG, icons):** “An effective icon is a graphic asset that expresses a single concept in ways people instantly understand” [https://developer.apple.com/design/human-interface-guidelines/foundations/icons](https://developer.apple.com/design/human-interface-guidelines/foundations/icons); app icons should “avoid cramming lots of different images into your icon. Find a single element that captures the essence of your app and express that element in a simple, unique shape” [https://developer.apple.com/library/safari/documentation/UserExperience/Conceptual/MobileHIG/AppIcons.html](https://developer.apple.com/library/safari/documentation/UserExperience/Conceptual/MobileHIG/AppIcons.html). Third-axis depth, bevels, and texture are exactly the “rich visual details” Apple reserves for app-icon art — not for the brand mark itself.
- **Google (brand guidelines):** force clear space and minimum sizes — “As a general rule, when details get difficultly to see, use a different logo layout” and “always keep a minimum clear space around the logo” (Google Season of Docs Brand Guidelines PDF [https://developers.google.com/static/season-of-docs/images/2019/logo/SeasonofDocs_BrandGuidelines.pdf](https://developers.google.com/static/season-of-docs/images/2019/logo/SeasonofDocs_BrandGuidelines.pdf); clear-space rule also in Android logo-lockup guidance [https://thepartnermarketinghub.withgoogle.com/brands/android/visual-identity/visual-identity/logo-lock-ups](https://thepartnermarketinghub.withgoogle.com/brands/android/visual-identity/visual-identity/logo-lock-ups)). A 3D mark that only reads large violates this.

**Rule for “Chief of Staff”:** ship a **flat SVG master first** (Playfair ‘C’ + wordmark, tuned to read at 16 px). 3D is allowed only as a *derived* layer: (i) hero/OG/social renders, (ii) interactive web moments (three.js), (iii) physical tokens (the extruded-C as a badge/pill via manifold3d/build123d STEP). Never let bevels, gradients, or specular highlights carry the identity. Any 3D variant must have a 16 px legibility check and a single-color fallback.

## 7. Recommendation + permissions

**Recommended chain (scriptable, headless, commercial-OK):**
1. `fontTools` → instance Playfair wght=900 (and 700/500 for steps).
2. `bpy` (Python 3.13 venv, EEVEE) for shaded stills; Cycles CPU/Metal for the final. Keep the flat SVG master as the single source of truth — derive 3D from it, never the reverse.
3. `build123d` for STEP/badge geometry + SVG projection line-art; `trimesh`+matplotlib for GL-free previews.
4. Optional web layer: three.js (`opentype.js` → `ExtrudeGeometry`) → `GLTFExporter` → either browser or Blender.

**Needs user permission (not done here):** (a) standalone Blender app / OpenSCAD app install (`brew install --cask blender/openscad`) — system-level installs were avoided; (b) Playwright/Puppeteer browser download for pure-three.js headless raster (or accept the Blender round-trip); (c) **any AI generation** (TRELLIS/Hunyuan/TripoSR) — Linux/CUDA-oriented, territory-licensed (Hunyuan), and wrong for a precise typeface.
